# Plan 1.1：基本功能稳定

## 目标

把现有看板收敛为一个稳定闭环：创建 Project，创建 Issue，关联当前 Codex Thread，更新状态，从 Issue 返回正确 Thread，并保证 macOS 与 Windows 行为一致。

## 范围

- 固化 Project、Issue、六种状态、五种优先级、置顶、搜索和单一主 Thread 关联行为。
- 明确 Runtime、SQLite、CLI 和注入面板之间的数据边界。
- 保证 Codex、Runtime 和注入器分别重启后数据与关联不丢失。
- 建立正式 schema migration；变更已有数据库前创建备份，数据库异常时拒绝写入。
- Issue 修改和归档保持版本冲突保护，不静默覆盖。
- 跨列移动时追加到目标列末尾，状态、排序和置顶重启后保持确定。
- CLI 与注入面板使用一致的错误码，失败操作不显示虚假成功。
- Thread 打开区分侧边栏确认、路由请求和打开失败。
- 明确空状态、连接失败、Thread 不存在和数据库不可写的用户结果。
- macOS 与 Windows 使用同一领域模型、API、CLI 和注入面板行为。

## 不包含

- 多 Agent、自动调度、worktree 和自动执行。
- 新视图、大规模视觉改版和独立 Web UI。
- 云同步、账号、统计和远程访问。
- 多 Thread、标签编辑界面、同列精细排序和 Project 并发版本锁。
- CDP 兼容规则模块化、在线升级和正式安装器，分别由 Plan 1.2、1.3、1.4 交付。

## 交付结果

- 一套稳定的本地领域模型和 API。
- CLI 与注入面板对同一 Issue 的操作结果一致。
- Thread 关联和打开行为具有明确成功或失败结果。
- Runtime 不可用时不损坏已有数据。
- 相同业务输入在 macOS 与 Windows 得到相同结果。

## 验收

- 全新数据目录可以完成完整闭环。
- 创建三张卡片并跨状态移动，重启后顺序和状态不丢失。
- 当前 Thread 能关联到 Issue，并从 Issue 打开同一 Thread。
- 搜索能按标题定位 Issue。
- 两个客户端使用旧版本同时写入时，旧写入被拒绝并提示冲突。
- Runtime 停止时面板显示可恢复故障，恢复后无需重建数据。
- 数据库 schema 升级前生成可恢复备份，损坏或不可写数据库不会被静默覆盖。
- macOS 与 Windows 分别完成 Runtime、CLI、看板和 Thread 往返验收。

## 回滚

停止 Runtime 和注入器，保留 SQLite 与备份；本模块不执行用户数据删除。
