# Plan：公开发布运营

## 目标

持续维护一个可安装、可升级、可理解、可反馈和可回滚的公开产品。公开发布已经发生，本计划不再以“第一次上线”为目标，而是约束 Stable、Preview、官网、文档和反馈处理。

## 当前基础

- GitHub 已有 Stable 与 Preview Release。
- macOS 与 Windows 已有公开安装入口。
- 官网、README、中英文说明和使用文档已经上线。
- GitHub Issue 已经出现真实用户反馈。
- Changelog、版本校验、签名资产和发布工作流已经建立。

## 范围

- Stable 与 Preview 使用明确版本、独立更新通道和一致的安装入口。
- 每个版本具有 Changelog、校验文件、安装资产、兼容声明和回滚路径。
- 官网、README 和文档只描述当前已验证能力，不把计划写成已上线功能。
- 发布前分别核对源码、CI、发布资产、安装结果和真实桌面行为。
- 公共反馈统一进入 GitHub Issue，再同步到本地看板进行排期和验收。
- 安装、数据、网络访问、更新、禁用、卸载和非 OpenAI 官方声明保持可见。
- 兼容性事故可以通过独立兼容层或完整版本在 24 小时内修复、回滚或撤回。

## 发布门槛

- 目标版本的 Changelog、版本字段、Tag 和发布资产一致。
- Apple silicon、Intel macOS 和 Windows 的目标安装路径均通过对应验收。
- 安装、重装、升级、回滚和卸载没有未解释的数据丢失或残留状态。
- 当前 Codex Stable 版本有兼容证据。
- Preview 中发现的阻塞级问题已经关闭、回滚或明确声明。
- 发布说明区分源码完成、CI 通过、资产发布和真实桌面验证。

## 反馈闭环

1. 确认反馈属于 Bug、认知缺口、体验改进、功能建议或不在范围。
2. 复现或取得足够证据后进入本地看板。
3. 修复在 Preview 验证，不直接把 `main` 上的实现称为已发布。
4. 进入 Stable 后更新公开 Issue，说明准确版本和升级路径。
5. 无法支持的需求给出产品边界，不长期悬置。

## 不包含

- 以 Star、下载量或群内分享替代激活和重复使用证据。
- 在安装与核心闭环不稳定时扩大推广。
- 为了发布节奏跳过 Changelog、资产校验或目标机器验收。
- 把 MCP、多端同步、独立界面或图式工作流提前宣传为现有能力。

## 验收

- 新用户只通过公开页面即可完成安装、理解产品边界并找到文档和卸载方式。
- 每个下载入口对应确定版本与可验证资产。
- Preview 问题不会静默进入 Stable。
- 每个公开反馈都有状态、版本边界和下一步动作。
- 发现数据、安全或广泛兼容问题时可以暂停安装入口并恢复上一个版本。

## 当前状态

本计划已经启动并持续进行。近期目标是完成 `v0.4.1` 稳定性收口和真实用户验证，不以新增发布渠道为优先事项。

## 回滚

发现数据、安全或广泛兼容问题时暂停对应下载入口，保留公告、文档和卸载说明；回滚兼容层或完整版本后再恢复发布。
