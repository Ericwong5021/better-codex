# Plan 2.1：最小开源治理

## 目标

建立公开仓库必须具备的信任、反馈和贡献边界，不在没有用户前搭建庞大社区体系。

## 范围

- 选择并加入正式开源 License。
- 提供安全问题的私下报告入口和响应范围。
- 提供精简贡献流程、开发环境和提交要求。
- 提供 Bug、兼容性问题和功能建议模板。
- 提供最小 PR 模板。
- README 明确本地数据、监听端口、读取范围、更新网络请求、统计策略和卸载方式。
- 明确声明项目与 OpenAI 无隶属或背书关系。
- 公布当前支持的操作系统与 Codex Desktop 版本范围。

## 不包含

- Discord、Founding 100、复杂治理委员会和大量预制 Issue。
- 为了显得活跃而创建没有真实需求来源的任务。
- 团队协作、商业授权和插件市场规则。

## 验收

- 陌生用户只阅读仓库首页即可判断安装条件、数据边界和退出方式。
- 安全问题不会被迫在公开 Issue 披露。
- 一个外部贡献者能按贡献指南完成本地开发和提交。
- Issue 模板要求提供平台、Codex 版本、core 版本、compatibility 版本和诊断信息。
- 仓库视觉和文案不暗示 OpenAI 官方产品。

## 回滚

治理文件可独立调整，不影响程序与用户数据；已发布 License 的历史版本不追溯改变。
