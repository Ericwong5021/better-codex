# Plan 2.2：小范围真实用户验证

## 目标

在已经公开可下载的基础上进行克制的小范围验证，用真实安装和使用证据决定是否扩大 Stable 推广以及是否启动多端同步。

## 样本与周期

- 招募 20 至 30 名经常使用 Codex Desktop 的用户。
- macOS 与 Windows 均需覆盖；每个平台至少 5 次有效安装尝试。
- 观察周期为 7 天。
- 不要求点赞、Star、转发或公开好评。

## 激活定义

```text
安装成功
→ 创建一个 Project
→ 创建三张 Issue
→ 关联一个 Codex Thread
→ 从 Issue 重新打开该 Thread
```

## 记录内容

- 安装是否成功、耗时和失败阶段。
- Codex、core 与 compatibility 版本。
- 是否完成激活。
- 是否在 7 天内第二次打开并推进任务。
- 用户主动描述的价值、疑虑和放弃原因。
- 仅收集用户明确同意提供的诊断信息，不收集对话正文。

## 决策门槛

- 安装成功率不低于 80%。
- 成功安装用户中，激活率不低于 50%。
- 至少 5 名用户在 7 天内重复使用。
- 没有未解决的数据丢失、安全残留或无法退出问题。
- 至少 5 名用户能不经解释说出产品解决的问题。

未达到门槛时返回 `v0.4.1` 稳定性收口或 Plan 2.3 修正，不扩大 Stable 推广，也不启动多端同步实施。

## 验收

- 每个失败都能归类为安装、兼容、认知、功能或体验问题。
- 高频问题有复现证据和优先级。
- 宣传文案使用真实用户语言，不使用未经验证的效果声明。

## 回滚

停止招募不会影响已安装用户；向测试用户提供稳定版本、降级和完整卸载入口。

## 当前进度

- 已经出现公开用户反馈和社区试用，但尚未形成统一样本表、平台分布、安装成功率、激活率和 7 天留存记录。
- 官网、README 和文档站已经具备基本承接入口。
- 下一步不是继续扩大曝光，而是建立同一口径的安装、激活、复用和失败分类记录。
- 在样本与指标完整前，本计划保持进行中。
